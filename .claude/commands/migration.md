# MigrationService

## Паттерн

Каждая миграция — отдельный тип реализующий `Migration`:
- `key: String?` — уникальный ключ для отслеживания выполнения. `nil` / пустая строка = запускается каждый старт
- `execute() async throws` — тело миграции
- log-and-continue: ошибка одной миграции не останавливает остальные

Упорядоченный массив миграций — порядок имеет значение.  
Swinject assembly с ручной сборкой `[Migration]` (не `autoregister`).

---

## Существующие миграции

### DecisionsCodableFormatFalloutMigration
Чинит коррумпированный формат решений:  
`[PhotoId: [String: [String: String]]]` → `[PhotoId: Decision]`

### DecisionsUrlToNameIdMigration
Мигрирует ключи решений: URL → имя файла.

**⚠️ Обе миграции сейчас `key: String? = nil`** — запускаются каждый старт. Прописать стабильные ключи когда формат данных стабилизируется.

---

## Добавление новой миграции

1. Создать тип реализующий `Migration`
2. Выбрать уникальный строковый ключ (или `nil` если нужно запускать каждый раз)
3. Добавить в массив в `MigrationsAssembly` в нужное место по порядку
4. Миграции выполняются один раз — повторный запуск пропускается по ключу
